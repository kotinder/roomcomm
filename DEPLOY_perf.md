# Деплой: путь записи, замер латентности, алерт

Ветка `feat/auth-mvp`, 4 коммита поверх того, что сейчас крутится на проде.
364 теста, ruff/mypy/`lint:ui` на базовом уровне. Схема прежняя: SCP + docker
rebuild, руками, без `git push`. ⚠️ Volume `commroom_data` НЕ трогать —
миграция отрабатывает сама при старте контейнера.

Что прод сейчас не умеет, и как это проверить за секунду:

    curl -s https://roomcomm.xyz/healthz
    # сейчас: {"ok":true,"inflight":0,"shed_total":0}
    # после:  ...,"db_busy_total":0,"requests_1m":..,"p50_ms":..,"p95_ms":..

Отсутствие `db_busy_total` — признак того, что на сервере код до `f0864f7`.

## 0. Что едет

| коммит | что меняет |
|---|---|
| `f0864f7` | одна UPDATE на пост вместо `COUNT(*)` + UPDATE TTL + UPSERT квоты; дневные счётчики в Redis пачкой; `busy_timeout`, WAL-чекпойнт с фонового потока, `mmap_size`; `database is locked` отвечает 503 + `Retry-After`, а не 500 |
| `b04b660` | каждый запрос измеряется, гистограмма по маршрутам в `route_stats`, таблица p50/p95 в `/admin` |
| `4c17645` | телеграм-алерт, когда p95 маршрута за сегодня втрое ушёл от предыдущих дней |
| `c59a782` | p50/p95 за последнюю минуту в `/healthz` |

`05fedc3` (фаза knock в нагрузочном тесте) — только `tests/`, на сервер не едет.

## 1. Что копировать

Только `app/`. `requirements.txt`, `Dockerfile`, nginx-конфиг и `static/` не
менялись — новых зависимостей нет. Новые файлы внутри: `app/latency.py`,
`app/posting.py`.

    scp -r app root@62.60.244.159:/home/deploy/commroom/app

## 2. Env

Нового задавать нечего. Но три переменные, которые уже должны быть, теперь
несут больше веса, чем раньше:

    docker exec commroom printenv REDIS_URL TG_BOT_TOKEN TG_CHAT_ID

- **`REDIS_URL`** — без него счётчики квот откатываются на UPSERT в SQLite, то
  есть примерно половина выигрыша `f0864f7` не случится, а дедупликация алерта
  выродится в «один раз на воркер на сутки» вместо одного раза вообще.
- **`TG_BOT_TOKEN` / `TG_CHAT_ID`** — без них алерт молча ничего не делает.
- Необязательное: `ROOMCOMM_PUBLIC_URL` — ссылка в теле алерта, по умолчанию
  `https://roomcomm.xyz`.

## 3. Rebuild

    cd /home/deploy/commroom
    docker build -t commroom .
    docker stop commroom && docker rm commroom   # контейнер, НЕ volume!
    docker run -d --name commroom --network commroom-net --restart unless-stopped \

## 4. Миграция — сама, при старте

Обе вещи идемпотентные и идут под тем же файловым локом, что и раньше, так что
два воркера не гонятся:

- **`rooms.messages_count`** — ALTER плюс разовый бэкфилл
  `UPDATE rooms SET messages_count = (SELECT COUNT(*) …)`: полный проход по
  `messages`, секунды на базе такого размера. Не опционален: без него лимит в
  1000 сообщений на комнату читался бы как 0 для всех существующих комнат.
- **`route_stats`** — новая таблица, создаётся `create_all`.

## 5. Проверка после старта (3 минуты)

    docker logs commroom --tail 30          # нет ошибок миграции
    curl -s https://roomcomm.xyz/healthz    # появились db_busy_total и p50/p95
    curl -s https://roomcomm.xyz/api/rooms | head -c 200   # старое живо

Создать комнату и запостить в неё сообщение (201), затем открыть `/admin` —
под «Usage» должна быть секция **Latency · today** с непустой таблицей.
`p50_ms`/`p95_ms` в `/healthz` первую минуту после старта будут `null`: окно
ещё заполняется, это нормально.

Чего ждать дальше: колонка «p95 · 7d» наполнится за несколько суток, и до тех
пор алерт молчит by design — сравнивать не с чем, пока на маршруте не наберётся
500 запросов за предыдущие дни.

## 6. Откат

Положить обратно предыдущий каталог `app/` и пересобрать. Схема совместима в
обе стороны: старый код не знает про `messages_count` (считает `COUNT(*)`, как
и считал) и про `route_stats` (просто не трогает её), так что откатывать базу
не нужно.

## 7. Чего этот деплой НЕ делает

- не включает `QUOTA_MODE=hard` — метрим, никого не режем, как и раньше;
- не трогает nginx и `deploy/nginx-commroom.conf`;
- не запускает нагрузочный прогон. Он отдельно, и для фазы knock нужен IP
  генератора в `RATE_EXEMPT_IPS` — иначе в неё упрётся собственный лимит
  приложения в 30 комнат/час. Порядок — в `tests/load/setup_prod.py`.
